## 这份文档管什么

只排期与拆任务，契约以[扩展中心设计](../extension-center/)为准。
估算口径：1 名熟悉本仓库的开发者、全职、含自测与文档；不含在线目录、签名与自动更新。
人日数是粗略量级，用于排序与取舍，不是承诺。

## v1 交付范围

1. 设置窗「偏好 / 壁纸 / 扩展」三个页签。
2. 扩展中心：已安装列表、过滤、详情、卸载、诊断。
3. 本地 ZIP 导入：选择文件 / 拖拽 → 预览确认 → 安装；scene 与 widget 共用一条管线。
4. Widget 启用、权限确认、逐能力撤销、打开 / 关闭 / 结束运行 / 停用。
5. Widget 包完整性（旁路摘要 + TOFU）与运行时复核。
6. 开发模式：挂载本地目录、打开、重载、关闭即销毁。
7. 托盘「扩展」子菜单；设置页工具列表接入已启用扩展。
8. 文档同步：`widget-package.md`、`content-format.md`、`architecture.md`、`README.md`。

## 完成定义（DoD）

- `pnpm check` 全绿（lint / typecheck / vitest / content:check / widgets:check / sdk:check）。
- `cargo test` 全绿，`cargo clippy` 无新增告警（仓库把 warning 当 error）。
- 新增命令同时出现在 `lib.rs` 与 `build.rs` 的 `APP_COMMANDS`。
- `pnpm widgets:gen` 生成的 capability 与代码一致，`pnpm widgets:check` 通过。
- 设计文档 §14 的手工验收清单逐项通过：安装、启用、打开、撤销 `network`、篡改、卸载、开发模式重载。
- 文档不再出现「工具没有安装器」「手动复制目录是唯一方式」这类过期表述。
- 旧版本安装的包不卸载也能在新版本继续加载。

排序原则：先打通一条端到端竖切（安装 → 列表 → 启用 → 打开），再补权限、开发模式、托盘。
任何阶段都不先做「在线市场」。

## 主要风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 设置页拆页签破坏现有测试与布局 | 中 | 先搬组件不改逻辑，测试选择器优先修 |
| 托盘动态菜单在 Windows 上重建异常 | 中 | 第一天做原型；失败则退化为「打开设置时刷新」 |
| 摘要扫描拖慢列表 | 低 | 单包 < 5 MiB；必要时按 mtime 缓存 |
| 撤销 `chrome` 让插件无法关闭 | 高 | 运行中锁定 + 宿主顶栏回退 |
| 范围蔓延到在线市场 / 更新 / 签名 | 高 | 非目标清单 + PR 评审卡口 |
| 文档与实现再次漂移 | 中 | DoD 包含文档，收尾阶段专门校对 |
| 旧命令下线导致遗漏调用 | 中 | `gen-widgets.mjs` 校验前端 `invoke` 字面量 |

## 发布与回滚

- 预发布阶段不引入 feature flag：功能随版本整体出现，减少分支。
- 回滚 = revert PR；已安装的 widget 目录与旧版本兼容，scene 完全不变。
- 托盘重建若在个别环境崩溃，保留设置页工具列表作为兜底入口，托盘功能可单独回滚。
- 新增字段都带默认值，旧版本读新文件时忽略未知字段。
