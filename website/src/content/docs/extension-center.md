## 一句话

在设置窗里增加一个统一的**扩展中心**：普通用户从文件安装、启用、授权、卸载，
开发者可以把本地目录挂进来热调试。后端**共享一条安装管线**，但 scene 与 widget
继续各用各的清单、摘要算法、能力白名单和运行时。

## 为什么需要它

仓库里原本有两套能跑、但互不相干的包系统：

| 维度 | Scene（Community） | Widget（Extensions） |
| --- | --- | --- |
| 清单 | `catalog.json` + 单条 scene | `widget.json`（schemaVersion 2） |
| 安装 | zip / 文件夹 + 整包摘要 + 目录签名 | 无安装器，手动复制目录 |
| 运行时 | `sandbox=""` iframe，不执行 JS | `sandbox="allow-scripts"` iframe + postMessage 桥 |
| 完整性 | 有摘要，运行时复核 | 无摘要，磁盘改动发现不了 |
| 生命周期 | 安装 / 卸载 | 启用 / 撤销，没有卸载 |

由此产生的问题很直接：普通用户拿不到工具扩展；可执行 JS 的那一类反而没有完整性校验；
「内容包」和「插件」两个入口让人不知道用哪个；装好的扩展也没有稳定的全局打开路径。

## 目标与非目标

做：一个扩展中心页面统一列出两类扩展；三个入口（应用内列表、本地 ZIP 导入、开发者本地目录）；
后端抽出共享安装管线（ZIP 安全检查、staging、原子安装、卸载清理、变更事件）；
widget 补上完整性、安装/卸载、逐能力授权、运行状态与错误诊断；安装、启用、运行三态解耦。

不做：在线目录与市场、自动更新与回滚、第三方签名与发布者信任链、把内置工具包化、
允许扩展建窗或调任意 Rust 命令、文件关联双击安装、跨平台，以及对 `allow-scripts` 扩展做「强沙箱」承诺。

## 术语

| 术语 | 含义 |
| --- | --- |
| 扩展 | 用户可安装的内容或工具总称，`kind = scene \| widget` |
| 包 | 一个目录 + 一份根清单（`catalog.json` 或 `widget.json`） |
| 适配器 | 某一 kind 的校验、摘要、安装落点与运行时入口 |
| 安装管线 | 与 kind 无关的解压、限流、staging、原子落地、事件 |
| 已安装 / 已启用 / 运行中 | 落盘通过校验 / 用户确认权限 / 宿主已建窗（可见或隐藏） |
| 开发包 | 开发模式挂载的本地目录，不复制、不锁摘要 |

## 信息架构

设置窗顶部三个页签：**偏好 / 壁纸 / 扩展**。v1 用页内状态切换，不新增路由、不新建窗口，
避免动 `window_host` 的窗口清单；「壁纸层」卡片单独搬进「壁纸」页签；工具窗口列表留在偏好里，
只管显示/关闭，启用与授权仍在扩展中心。

扩展页的结构：已安装计数（工具 / 壁纸）+ 操作区（从文件安装 / 打开目录 / 刷新），
过滤 chip（全部 / 工具 / 壁纸），卡片流，拖拽区，底部开发模式开关。

## 状态模型

```text
             install                enable                 open
  (未安装) ──────────► 已安装 ──────────────► 已启用 ──────────────► 运行中
                        │                      │                    │
                        │  uninstall           │  disable           │  close / stop
                        ▼                      ▼                    ▼
                     (未安装) ◄────────────────┴────────────────────┘
```

- **安装不执行扩展代码**：只做文件校验与落盘，不创建 WebView。
- **启用才授权**：展示权限说明，用户确认后写入授权账本与清单快照。
- **打开才建窗**：仍走受控的 `open_window` 路径。
- 关闭行为由清单 `lifecycle` 决定：`background` 关闭 = 隐藏（JS 继续跑），`suspend` 关闭 = 销毁窗口。
- **结束运行** = 销毁窗口，状态 KV 保留；**停用** = 销毁窗口 + 撤销运行资格；**卸载** = 再删授权、状态与文件。

Scene 没有「启用 / 运行」概念，只有安装、卸载与「正在被壁纸引用」的判断。

## 共享安装管线

```text
source (.zip / 目录)
  ├─ 1. 解压/复制到 .staging-<随机>
  │      拒绝 .. / 绝对路径 / 反斜杠 / NUL / 符号链接；
  │      文件数 ≤ 512，单文件 ≤ 8 MiB，整包 ≤ 64 MiB
  ├─ 2. 定位包根（允许 ZIP 外层套一层目录）
  │      catalog.json → scene；widget.json → widget；
  │      两者都有 → 歧义错误；都没有 → 缺清单错误
  ├─ 3. 交给适配器校验清单、id、entry、能力、兼容性、许可与摘要
  ├─ 4. 冲突检查：scene 覆盖前备份旧目录；widget 已存在则拒绝
  ├─ 5. 原子落地 rename(bundle, root/<id>)
  └─ 6. 广播 extensions-changed，清理 staging
```

失败只删 staging，不碰已安装内容；启动时清理超过 24h 的 `.staging-*` 残留。

**两步确认**：UI 先调 `extensions_inspect(path)` 做一次无副作用校验，弹出确认框
（名称、版本、作者、许可、kind、能力、网络源、体积），确认后再调
`extensions_install(path, sourceDigest)`；安装器重新校验并比对指纹，两次之间包被改动
就返回 `package.changed`，不落盘。安装确认只回答「装什么」，权限仍在启用时授予。

## 权限模型

三组集合：**declared**（清单声明）、**granted**（授权账本）、**effective**（`declared ∩ granted`，
再叠加宿主强制规则）。

| 能力 | 强制点 | 撤销后的实际效果 | 级别 |
| --- | --- | --- | --- |
| `widget.ui` | 无 | 始终可用 | 基础 |
| `widget.theme` | 不再下发主题消息 | 停留旧配色 | 提示 |
| `widget.state` | `require_grant` | 状态命令返回 `denied` | 强制 |
| `widget.audio` | `requestAudio` 返回 false | iframe 仍可自行发声 | 提示 |
| `widget.media` | 文件选择返回 denied | 仍可用浏览器原生选择 | 提示 |
| `widget.network` | CSP 只留包自身源 | 外部请求被拦截 | 强制 |
| `widget.chrome` | 拒绝拖拽/最小化/关闭/透明 | 回退宿主顶栏 | 强制 |

**清单漂移**：启用时把 `widget.json` 的 SHA-256 与能力快照写进授权账本；扫描时哈希不一致
即 `needs-review`——不加载、不建窗，卡片提示重新确认权限。这补上了「摘要只能证明文件没变、
不能证明能力没变」的缺口。

## 必须说清楚的边界

- `allow-scripts` + postMessage **不自动构成安全沙箱**：它只保证 iframe 拿不到宿主 DOM 与存储，
  不保证插件不联网、不发声、不消耗 CPU。
- **摘要不是签名**：它证明「没被改过」，不证明「是谁做的」。
- **启用不是安全审计**：权限界面展示的是宿主实际能强制执行的能力，提示级能力要标注。
- 不承诺「任意代码插件系统」：扩展仍是静态 Web 包，不能建窗、不能调任意 Rust 命令、不能碰 Win32。
